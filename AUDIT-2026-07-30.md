## P1 — Client-facing wrong numbers (fix first)

1. **PDF "Success Rate" is always 100%.** headless_runner.py:334 calls
   compute_scenario_summary without spending_target; success = 1 − P(after_tax_end < $0),
   and balances can't go negative (guardrails cut spending instead). Reproduced: plan
   with median ending $3,815 → PDF headline "100% Success Rate. Your portfolio lasted
   the full plan…" (pdf_report.py:376–380). Every quick-sim PDF ever generated carries
   this. Fix: report spending_success_rate (plan-met %) instead, or default
   ending_balance_goal to $1 and relabel honestly.
2. **run_full_process.py has its own unfaithful param builder** instead of the
   known-good plan_to_sim_params.build_sim_params_from_plan:
   - drops multi-period spending (only periods[0], run_full_process.py:26–28)
   - drops ALL add_goals (lines 99–119)
   - hardcodes roth_conversion_mode='none' (line 82) — saved conversion ladders
     silently ignored
   - filing_status: only literal "Married Filing Jointly" → mfj; "mfj" → taxed single
     (line 75)
   - drops pension buyout + all annuity income params entirely
   - Bootstrap mode silently runs lognormal (no return_mode= passed, lines 127–138, 316)
   - default divergences vs UI: fee 0 vs 120 bps, guardrail cap 25/50 vs uncapped,
     state_exempt_retirement False vs True, fill rate .24 vs .22, inheritor rate .32 vs .35
   Fix: delete build_sim_params, use plan_to_sim_params (its docstring already says so).
3. **scenario_matrix / compare_modes run historical windows off the 100E/100F blend**
   (get_all_historical_windows called without target_stock_pct /
   use_actual_allocation_columns — scenario_matrix.py:557, compare_modes.py:57), so the
   whole comparison table is at a different effective allocation than the UI. Also uses
   a third success definition ("Survival %" = end > 0).
4. **Comfort level mismatch:** run_full_process honors --shortfall-pct but
   html_report.py:467,475 hardcodes 80% for the displayed dollar + label.
5. **PDF income table** (pdf_report.py:540–646) is per-column independent medians
   presented as "the typical path" — columns don't sum, and the chart below uses a real
   run. Same issue in the Bad/Typical/Good splice (480–501).
6. **Historical PDFs say "1000 rolling periods"** when 829 ran (headless_runner.py:493
   uses plan num_sims, discards len(results)).

## P2 — Silent biases in the interactive app

7. **Pension buyout × scenario annuity merge bugs** (sim_engine.build_scenario_params):
   annuity_purchase uses `=` not `+=` (lines 860/864) and the direct-key loop
   (909–912) lets buyout keys overwrite purchased-annuity income — combining the
   dedicated buyout comparison with a scenario annuity silently drops one income
   stream while still charging for it (main.py:986–988 merge order).
8. **Phase-1 auto-spending biases the buyout comparison:** main.py:1147–1155 adds
   buyout annuity income to the 4% base but not the lump sum — the two sides of
   lump-vs-annuity run at different spending levels.
9. **Guardrail sigma inconsistency (lognormal mode):** baseline uses correlation-
   adjusted sigma (main.py:895–902, ρ=0.10); scenarios use linear blend
   (sim_engine.py:831) ≈12% higher at 60/40 — spurious deltas in allocation
   comparisons. Historical/bootstrap path is correct.
10. **Spending-success metric vs multi-period plans:** all success metrics compare
    lifetime-average spending to period-1 amount (main.py:1378 etc.) — go-go/slow-go
    plans score far too low and Phase-3 solver overreacts.
11. **annuity_start_year is one global scalar** for both people (sim_engine.py:867).

## Known engine simplifications (documented, acceptable, disclose as needed)

- Non-qualified (taxable-funded) annuity income taxed 100% ordinary — no exclusion
  ratio → biased AGAINST taxable-funded SPIA purchases.
- Full basis step-up at first death (community-property style); IL common-law would
  be half step-up on joint accounts.
- No pre-65 ACA subsidy modeling (matters for early-retiree Roth ladders).
- RMD start age manual (won't auto-shift to 75 for born ≥1960).
- Flat state tax; all dividends qualified; pro-rata basis; no AMT / TDA basis /
  Roth 5-year clocks / SS earnings test.
